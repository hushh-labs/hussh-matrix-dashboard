# Private UAT detail worker (disabled by default)

The separately approved `one-agent-detail-daily-starts` policy limits new UAT parent job admissions to at most four per UTC day across viewers and selections. Existing active jobs and fresh publications coalesce without another admission; uncertain work is not refunded. The day is sampled from the runtime instance's UTC clock and rechecked before writes, so this is not a strict real-UTC guarantee under cross-instance clock skew. Jobs admitted before midnight may execute later; this is an admission limit, not a limit on native executions per day. The existing canonical native job and byte budgets remain authoritative.

`npm run metrics:uat-detail-worker` invokes the separate UAT-only listener. It refuses startup without the explicit listener/service/detail flags and fixed service configuration. Starting the process alone does not read Firestore, contact identity or submit warehouse/queue work. The listener authenticates the fixed web or task service account before constructing the runtime, which independently rechecks identity and approved policies. Cloud ingress, IAM, source identity, policy and cost budgets must be independently qualified before enabling it.

The dispatcher is separately disabled by default and requires its own approved, unexpired policy bound to the complete service policy and fixed dispatcher identity. Deterministic enqueue uses lookup-only recovery after uncertainty; an unverified existing task is not treated as proof. This entrypoint alone does not provide a qualified end-to-end refresh. Shutdown aborts in-flight requests and bounds connection draining; already dispatched operations remain uncertain and require their durable reconciliation. Slow-body tests are synthetic, not production ingress qualification.

For an explicitly authorized operator, `npm run metrics:uat-detail-reconcile -- <job-id>` sends one lookup-only request using the caller's existing ADC. It requires `METRICS_UAT_OPERATOR_RECONCILE_ENABLED=true`, the exact service configuration and the approved dispatcher identity and policy. The server rechecks those controls. This command does not initiate impersonation or create a replacement task, and it does not retry a missing/unknown result; ambient ADC provenance must be verified separately. a 404 or ambiguous enqueue remains held for separate reconciliation. Do not put tokens or account data in arguments or logs.
