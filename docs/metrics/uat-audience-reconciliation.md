# UAT audience admission: uncertain request handling

The admission ledger charges one page before an upstream read. If authorization or cancellation prevents dispatch, the claim is completed and concurrency is released; the daily charge remains. After dispatch, a timeout, abort, broken response or uncertain transaction leaves the claim open and charged. A fully consumed, validated response completes the claim. There is no automatic expiry, retry or refund.

An open claim may exhaust the configured concurrent limit. An operator can inspect the claim and the global and viewer counters in the canonical database without reading account identities. Pause new audience admissions and preserve the claim, policy revision, counters and relevant operation evidence. Do not delete or edit claims, decrement counters, rotate the viewer key, change databases, or raise limits to clear the condition. Escalate the operation for review.

The current UAT One audience contract does not carry the admission operation ID and does not return a durable terminal receipt for it. A client timeout, a server request timeout, an absent log entry or elapsed time alone therefore cannot prove that the upstream work has stopped. The current implementation has no safe operator action that releases an uncertain dispatched claim. Do not activate this policy until a separately reviewed reconciliation mechanism can establish terminal status for the exact operation and atomically complete that claim without refunding the daily count. A separately authorized manual intervention must preserve evidence and cannot be represented as an automated guarantee.

Before any activation, verify a single canonical project/database/key version and approved finite policy across every reachable revision, including tagged revisions. Drain prior unguarded requests and exclude old unguarded revisions. Rollbacks must use the same guarded binding and ledger. The signed dashboard session can remain valid for up to eight hours after external account revocation; repeated role checks do not establish immediate Google-side revocation.
